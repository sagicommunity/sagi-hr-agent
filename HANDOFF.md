# HANDOFF — Sagi HR (hr.sagibonus.com)

Этот файл — передаточный документ для новой сессии/чата без контекста. Прочитай его целиком перед тем как что-то менять в проекте.

## 1. Что это за проект

`sagi-hr-agent` — внутренняя HR-система для отдела продаж Sagi (найм, обучение стажёров, панель руководителя). Владелец — Sagi (бизнес-почта business@sagibonus.com). Общаемся с ним на русском.

- Репозиторий: `https://github.com/sagicommunity/sagi-hr-agent` (публичный)
- Прод: `https://hr.sagibonus.com` (Vercel, автодеплой с ветки `main`)
- Стек: статические HTML-страницы + Vercel Serverless Functions (Node, `api/*.js`) + Upstash Redis (REST API) как хранилище.

## 4. ГРАБЛИ — на них уже наступали, не наступать снова

1. **git-репозиторий в песочнице УСТАРЕЛ и не является источником правды.** Деploy идёт НЕ через `git push` из этой песочницы (сеть туда не пускает — см. п.6), а через веб-загрузку файлов на GitHub (`Upload files` UI). Локальный `git log`/`git diff` в `/tmp/sagi-hr-agent` показывает старый HEAD и вводит в заблуждение (например, `git diff` покажет «изменения» в файлах, которые на самом деле уже отличаются от HEAD ещё до твоих правок). **Не ориентируйся на git history — ориентируйся на реальное содержимое файлов в рабочей директории и на то, что реально задеплоено (проверяй через Vercel API и живой сайт).**

2. **Redis-оверрайды в `api/lessons.js` могут молча перекрывать правки в `lessons.js`.** У Sagi есть режим live-редактирования модулей обучения прямо в панели («Материалы обучения» → «Править») — это пишет оверрайд в Redis (`HASH hr:lessons`), который **имеет приоритет** над содержимым файла `lessons.js` на клиенте. Если отредактировать `lessons.js` и задеплоить, а для этого модуля уже есть оверрайд — правка в файле НЕ будет видна на сайте, и это не будет ошибкой деплоя, просто тихо не сработает. **Перед правкой lessons.js всегда сначала проверяй, нет ли оверрайда**, через JS в консоли открытой вкладки:
   ```js
   const r = await fetch('/api/lessons', {method:'POST', headers:{'content-type':'application/json'}, body: JSON.stringify({action:'public'})});
   const j = await r.json();
   Object.keys(j.overrides||{})
   ```
   Если id модуля там есть — либо снимай оверрайд через сам интерфейс (кнопка «Сбросить»/reset в редакторе), либо редактируй через сам live-редактор, а не через git-файл.

3. **Комментарий-поле коммита на GitHub Upload UI регулярно «промахивается» фокусом.** После клика по полю ввода commit summary фокус иногда уходит на соседний элемент (например, на ссылку «choose your files»), особенно если раскладка страницы отличается (разное число загруженных файлов). **Всегда делай скриншот сразу после клика**, чтобы убедиться, что фокус реально в поле (синяя рамка вокруг текстового поля с плейсхолдером «Add files via upload»), и только потом печатай текст коммита.

4. **Скриншот сразу после навигации на `?boss=1` может показать «пустой» экран входа вместо панели руководителя** — это не баг, а таймингова артефакт: рендер идёт асинхронно (сначала проверяется сохранённый пароль в localStorage, потом подгружаются пользователи). Подожди 1–2 секунды и сделай скриншот заново, прежде чем делать вывод, что что-то сломалось.

5. **Не убирай `#bossTableWrap{overflow-x:auto}`** у таблицы сотрудников в `index.html` — без него таблица (12 колонок) при узком окне утаскивает за собой весь layout вбок вместе с боковым меню (см. п.2.5 выше). Это реальный баг, который уже был у Sagi и был исправлен.

6. **Сеть из этой облачной песочницы наружу ограничена allowlist'ом** — прямой `curl`/`fetch` на `hr.sagibonus.com` или `github.com` из Bash не работает (проксируется и блокируется, 403). Для любых проверок живого сайта или Redis-состояния используй Chrome-инструменты (`mcp__claude-in-chrome__javascript_tool` — выполняет JS прямо во вкладке, у которой есть доступ) или сам браузер, а не bash/curl/node-fetch.

7. **Пароль руководителя — один общий на все админ-эндпоинты** (переменная окружения `DASHBOARD_PASSWORD` в Vercel), и на клиенте он держится в единой SSO-сессии через `localStorage['sagiHR_ropPass']`. Не создавай отдельных паролей/форм входа на новых страницах — подключайся к существующей SSO-схеме.

8. **Публичного входа для руководителя на сайте больше нет и не должно быть** — это осознанное решение Sagi (боится, что обычные менеджеры увидят намёк на админку). Вход только через приватную ссылку `?boss=1`. Не возвращай кнопку/пилюлю входа руководителя на стартовый экран.

9. **`checklist.html` намеренно без пароля** — им пользуются не только руководитель, но и обычные менеджеры (для оценки звонков/встреч). Не добавляй туда гейт без явного запроса.

## 6. Как делать деплой (единственный рабочий способ — веб-загрузка на GitHub)

`git push` из этой песочницы **не работает** (сеть блокирует прямые запросы к github.com/hr.sagibonus.com — см. граблю №6). Единственный проверенный способ — загрузка файла через веб-интерфейс GitHub с помощью браузерных инструментов (`mcp__claude-in-chrome__*`).

Пошагово:

1. Отредактируй нужный файл в `/tmp/sagi-hr-agent/<file>` (или где он у тебя лежит).
2. **Синтакс-чек перед деплоем** (обязательно, ловит опечатки в escaping):
   ```bash
   node -e "
   const fs = require('fs');
   let s = fs.readFileSync('index.html','utf8');
   const scripts = [...s.matchAll(/<script>([\s\S]*?)<\/script>/g)];
   scripts.forEach((m,i)=>{ try{ new Function(m[1]); console.log(i,'OK'); } catch(e){ console.log(i,'ERR',e.message); } });
   "
   ```
   Для `lessons.js` — он не HTML, это чистый JS-файл (`window.LESSONS = {...}`), проверяется так:
   ```bash
   node -e "global.window={}; new Function(require('fs').readFileSync('lessons.js','utf8'))(); console.log('OK', Object.keys(global.window.LESSONS))"
   ```
3. Скопируй файл в папку стейджинга:
   ```bash
   cp /tmp/sagi-hr-agent/index.html /mnt/user-data/outputs/index.html
   ```
4. В браузере (Chrome-инструменты, если не загружены — сначала `ToolSearch` с `select:mcp__claude-in-chrome__tabs_context_mcp,...`) открой `https://github.com/sagicommunity/sagi-hr-agent/upload/main`.
5. Найди инпут загрузки файлов через `find` (запрос вроде "Choose your files"), загрузи файл через `file_upload` (путь — из `/mnt/user-data/outputs/`).
6. Кликни по полю commit summary и **сразу сделай скриншот**, чтобы убедиться, что фокус реально там (грабля №3 выше). Если фокус не там — кликни ещё раз точно по видимому текстовому полю.
7. Впечатай осмысленное сообщение коммита (на английском, коротко, в духе предыдущих: `Fix: ...`, `Boss panel: ...`, `Training: ...`).
8. Нажми «Commit changes».
9. Подожди ~15–20 секунд, затем проверь новый деплой через Vercel:
   ```
   mcp__Vercel__list_deployments { projectId: "prj_tSBdHWk8dxjYWAZ1Z6qTENWWUDVd", teamId: "team_qHemd62Mfi8aNIrfBTc18aAw" }
   ```
   Ищи самый свежий деплой с нужным `githubCommitMessage`, дождись `state: "READY"`, убедись что в `alias` есть `hr.sagibonus.com`.
10. Зайди в браузере на `https://hr.sagibonus.com/?boss=1` (или конкретную страницу) и визуально проверь изменения. Не забывай про грабли №4 (подожди 1–2 сек перед скриншотом после навигации).

## 7. Как проверить, что реально задеплоено (без доверия к git)

Раз git-история не отражает прод, для сверки «что сейчас живое» используй:
- Vercel `get_deployment` по последнему deployment id — там есть `githubCommitMessage` и `alias`.
- Сам живой сайт через Chrome (визуально или через `javascript_tool` — можно, например, зафетчить `/api/lessons` с `action:'public'` прямо из вкладки, чтобы посмотреть текущие Redis-оверрайды, см. граблю №2).
